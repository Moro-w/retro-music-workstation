# 复古音乐工作站｜项目概述

> 归档日期：2026 年 9 月 2 日  
> 当前版本：V0.1  
> 产品名称：暂用“复古音乐工作站 / RETRO MUSIC”

## 一、项目定位

复古音乐工作站是一款面向非专业音乐创作者的 AI 音乐生成 Web 产品。用户不需要学习编曲软件或专业提示词，只需用自然语言描述想要的画面、情绪和风格，系统便会将模糊想法整理成适合音乐模型理解的指令，并异步生成一段可播放、下载和管理的音乐。

产品以 80—90 年代电脑桌面为交互外壳，将创作台、播放器、历史记录和回收站组织成一套复古 Windows 工作站体验。复古视觉不是单纯装饰，而是用熟悉的“桌面—图标—窗口”结构，降低 AI 音乐工具的陌生感，并形成鲜明的产品识别度。

## 二、目标用户

### 核心用户

- 想快速生成配乐，但不会作曲、编曲或使用专业音乐软件的普通创作者。
- 需要为短视频、播客、游戏 Demo、展览或个人内容寻找氛围音乐的内容创作者。
- 对复古电脑、像素文化和电子音乐视觉有兴趣，希望创作过程本身具有趣味性的年轻用户。

### 用户特征

这类用户通常能说清“想要什么感觉”，却不熟悉 BPM、调性、乐器组合、歌曲结构和混音等专业表达。他们关注的不是复杂参数，而是能否快速把脑中的场景转化为一段可用、可保存的音乐。

## 三、用户需求

| 用户问题 | 对应需求 | 当前产品方案 |
| --- | --- | --- |
| 不会写专业音乐 Prompt | 低门槛表达创意 | 用户输入一句自然语言描述，AI 自动补全风格、节奏、乐器和结构信息 |
| 描述太模糊，担心生成结果失控 | 提高意图表达的完整度 | 提供“润色”功能，并在正式生成前自动执行一次音乐提示词优化 |
| 音乐生成需要等待，不知道是否卡住 | 看得见生成状态 | 任务异步排队，通过实时事件显示排队、处理中、进度和成功/失败状态 |
| 生成后找不到作品或难以继续使用 | 管理和复用生成资产 | 提供常驻播放器、历史记录、下载、软删除、还原和彻底删除 |
| 普通 AI 工具体验同质化 | 更有记忆点的创作环境 | 使用 Landing、BIOS 开机动画、复古桌面、窗口和任务栏构成完整工作站体验 |
| 线上多人试用时数据容易混在一起 | 基本访问与数据隔离 | 可启用邀请码登录，并按用户隔离生成记录和音频访问 |

## 四、核心使用场景

### 1. 为具体内容快速生成配乐

用户准备制作一条“夏夜海边”主题的短视频，在创作台输入“夏夜海边的篝火，轻柔吉他”，补充“Chill、温暖、慢节奏”等风格后生成约 45 秒音乐。完成后可直接试听并下载，用于后续剪辑。

### 2. 只有情绪，没有专业音乐方案

用户只知道自己想要“适合晚上开车听、放松一点”的音乐。AI 将其转化为包含核心风格、情绪、BPM、调性、主要乐器、发展结构和制作质感的英文音乐 Prompt，再交给音乐生成模型执行。

### 3. 连续试做并管理多个版本

用户围绕同一主题多次生成，作品自动进入历史记录。用户可以逐首试听、下载，把不满意的版本移入回收站，也可以在误删后还原。

### 4. 以复古电脑方式体验 AI 创作

用户从品牌首页进入 BIOS 启动画面，再进入桌面并双击“创作台”图标开始生成。这个场景强调探索感和沉浸感，适合个人作品展示、活动体验和小范围邀请试用。

## 五、产品主流程

```text
进入产品
  → 邀请码校验（线上可选）
  → Landing 与 BIOS 启动页
  → 进入复古桌面
  → 打开创作台
  → 输入音乐描述与风格
  → 可选：点击“润色”补全概念
  → 二次确认生成
  → AI 自动优化音乐 Prompt
  → 提交音乐模型并显示实时进度
  → 生成完成后自动进入播放器与历史记录
  → 试听 / 下载 / 删除 / 还原
```

## 六、Agent 架构

### 6.1 架构结论

当前版本采用“单核心 Agent + 确定性任务编排”的结构，而不是多 Agent 自主协作。

- **Agent 负责理解创作意图**：把用户的日常语言转换成音乐模型更容易执行的专业描述。
- **程序负责稳定执行流程**：创建任务、排队、选择音乐引擎、推送进度、保存音频和管理历史。
- **音乐模型负责生成音频**：它是 Agent 调用的生成能力，不等同于 Agent 本身。

这种结构适合当前 MVP：关键决策集中、执行路径可追踪，也便于以后替换 LLM 或音乐模型。

### 6.2 Agent 与系统协作关系

```text
用户输入：音乐描述 + 风格标签
              │
              ▼
┌─────────────────────────────┐
│ 音乐创作 Agent（LLMService） │
│ 1. 可选：概念润色            │
│ 2. 自动：TTM Prompt 优化      │
│ 3. 失败时：保留原始描述兜底   │
└──────────────┬──────────────┘
               │ 英文音乐 Prompt
               ▼
┌─────────────────────────────┐
│ 任务编排器（JobService）      │
│ 建任务 → 排队 → 状态流转      │
│ → 调用 Provider → 写库/落盘   │
└──────────────┬──────────────┘
               │
               ▼
┌─────────────────────────────┐
│ 音乐生成 Provider            │
│ fal.ai / ACE-Step / 302.AI   │
│ / Mock 开发兜底              │
└──────────────┬──────────────┘
               │ 音频文件 + 任务结果
               ▼
       播放器 / 历史 / 下载 / 回收站
```

### 6.3 核心 Agent 的输入输出契约

| 项目 | 定义 |
| --- | --- |
| Agent 目标 | 在不改变用户核心意图的前提下，提高音乐描述的完整度、风格一致性和场景匹配度 |
| 输入 | 用户原始音乐描述、可选风格标签，以及用户明确指定的 BPM、调性、乐器或禁止条件 |
| 主要判断 | 识别风格、情绪、场景、节奏、乐器和限制；信息不足时采用保守补全，不堆叠冲突元素 |
| 输出 | 一段 50—100 个英文单词的音乐生成 Prompt，不包含解释或 Markdown |
| 当前规则 | 主流程按约 45 秒的纯器乐生成设计；保留用户明确要求，避免刺耳失真、突兀转调和混乱编排 |
| 失败兜底 | LLM 未配置或请求失败时，直接保留用户原始描述，生成任务仍可继续 |
| 完成条件 | 获得非空的优化 Prompt，并交给任务编排器调用音乐 Provider |

### 6.4 辅助能力

- **概念润色**：由用户主动点击，把一句简单想法扩展为更有画面感的主题，并返回 3—5 个风格标签。
- **自动命名**：生成完成后根据用户描述或歌词上下文补充作品标题；属于后处理能力，不参与音乐内容生成。
- **Provider 路由**：支持 fal.ai CassetteAI、本地 ACE-Step、302.AI 和 Mock。`auto` 模式按已配置的云端能力、本地引擎和 Mock 依次兜底；当前环境明确指定 fal.ai。
- **实时事件通道**：通过 SSE 向前端发送排队、生成进度和最终状态，确保长耗时任务不会依赖一个持续等待的普通请求。

## 七、系统与数据结构

- **前端**：React + TypeScript + Vite，以单页应用实现 Landing、BIOS、桌面、窗口、创作台、播放器、历史和回收站。
- **后端**：FastAPI 提供登录、生成任务、任务查询、音频播放与下载等接口。
- **任务状态**：`queued → processing → completed / failed`。
- **数据持久化**：SQLite 保存用户、Prompt、风格、状态、标题、音频路径和生成耗时等记录；音频文件单独落盘。
- **访问控制**：线上可开启邀请码；接口按用户校验任务归属，播放和下载链接携带登录令牌。
- **模型解耦**：音乐生成统一封装为 Provider，替换底层模型时不需要重做上层产品流程。

## 八、当前版本边界

### 已实现

- 邀请码登录与用户数据隔离。
- 品牌首页、BIOS 动画、复古桌面、窗口和任务栏播放器。
- 音乐描述与风格输入、概念润色、自动 Prompt 优化。
- 异步生成、实时进度、播放、下载、历史记录和回收站。
- fal.ai CassetteAI、本地 ACE-Step、302.AI 与 Mock Provider 接口。

### 尚未完成

- “灵感、收藏、歌单、参考音频、设置”目前仍是占位入口。
- 当前前台创作表单没有开放歌词、参考音频、时长和 Seed 等高级控制项。
- 尚未形成基于用户反馈自动反思、重写 Prompt 或比较多版结果的闭环 Agent。
- 生成质量、速度和成本仍受实际音乐服务商影响；Mock 只用于免费开发测试，不能代表真实 AI 音乐效果。

## 九、项目价值

该项目验证的重点不是简单接入一个音乐生成 API，而是把“普通人的模糊创意”转化为一条可完成、可等待、可管理的音乐创作链路。其核心产品价值由三部分组成：自然语言降低创作门槛，Agent 提高输入质量，复古工作站建立差异化体验。现阶段已经形成从输入、理解、生成到资产管理的最小闭环，可继续扩展为更完整的个人音乐创作工作台。
